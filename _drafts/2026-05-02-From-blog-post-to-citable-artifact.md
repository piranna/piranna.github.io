## DOI, Reproducibility, and Long-Term References

One thing I wanted from the beginning was ensuring the experiment remained
citable and reproducible beyond a temporary GitHub repository.

The project therefore includes:

- a public GitHub repository
- detailed architectural documentation
- implementation notes
- Mermaid diagrams
- and a DOI-backed archival reference through Zenodo

That DOI turns the repository into a stable long-term reference instead of just
another disposable PoC.

This matters more than it initially seems.

A large amount of experimental systems knowledge disappears over time because:

- repositories vanish
- dependencies break
- links die
- architectural context gets lost

Treating technical experiments as archival artifacts instead of temporary code
dumps changes how they can be reused later.

Especially for:

- architectural studies
- benchmarking
- protocol explorations
- educational references
- future iterations

This also connects with a broader idea I've been increasingly interested in
recently:

> technical writing should explain the system, while the repository proves it.

The article becomes the canonical conceptual reference.

The repository becomes the executable evidence.
